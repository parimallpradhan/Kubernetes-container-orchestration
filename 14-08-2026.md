# 1. Kubernetes Cluster

### What is a Cluster?

A **Kubernetes cluster** is the complete Kubernetes environment containing:

* Control Plane
* Worker Nodes
* Kubernetes objects such as Pods, Services, Deployments, etc.

### Check cluster information

```bash
kubectl cluster-info
```

**Explanation:** Shows the Kubernetes control-plane and core service endpoints.

### Check Kubernetes version

```bash
kubectl version
```

Or:

```bash
kubectl version --short
```

> On newer Kubernetes versions, `--short` may not be supported, so `kubectl version` is safer.

### See cluster nodes

```bash
kubectl get nodes
```

Example:

```text
NAME           STATUS   ROLES           AGE   VERSION
controlplane   Ready    control-plane   10m   v1.34.x
node01         Ready    <none>          8m    v1.34.x
```

### Detailed node information

```bash
kubectl describe node node01
```

### Important student concept

```text
Kubernetes Cluster
       |
       +---- Control Plane
       |
       +---- Worker Node
       |
       +---- Worker Node
```

# 2. Namespace

### What is Namespace?

A Namespace logically separates resources inside a cluster.

For example:

```text
Cluster
 |
 +-- dev
 |    +-- Pods
 |    +-- Services
 |
 +-- test
 |    +-- Pods
 |    +-- Services
 |
 +-- prod
      +-- Pods
      +-- Services
```

### See namespaces

```bash
kubectl get namespaces
```

Short form:

```bash
kubectl get ns
```

### Create namespace

```bash
kubectl create namespace dev
```

### Verify

```bash
kubectl get ns
```

### Create Pod inside namespace

```bash
kubectl run nginx --image=nginx -n dev
```

### See Pods in dev

```bash
kubectl get pods -n dev
```

### See Pods in all namespaces

```bash
kubectl get pods -A
```

### Delete namespace

```bash
kubectl delete namespace dev
```

**Important:** Deleting a Namespace deletes the resources inside it.


A Pod uses a Namespace in YAML through the **`metadata.namespace`** field.

### 1. Create a namespace

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: dev
```

Apply it:

```bash
kubectl apply -f namespace.yaml
```

---

### 2. Create a Pod inside that namespace

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
  namespace: dev
spec:
  containers:
    - name: nginx
      image: nginx
      ports:
        - containerPort: 80
```

The important line is:

```yaml
metadata:
  namespace: dev
```

It means:

```text
Kubernetes Cluster
       |
       +---- Namespace: dev
                |
                +---- nginx-pod
```

### 3. Apply the Pod

```bash
kubectl apply -f pod.yaml
```

### 4. Check the Pod

If you run:

```bash
kubectl get pods
```

you may not see it because `kubectl` is looking in the **default namespace**.

Use:

```bash
kubectl get pods -n dev
```

or:

```bash
kubectl get pods --namespace=dev
```

### 5. See Pods in all namespaces

```bash
kubectl get pods -A
```

You will see something like:

```text
NAMESPACE   NAME         READY   STATUS
dev         nginx-pod    1/1     Running
```

### A **Namespace does not belong to the Pod specification**. It belongs under `metadata`:

```yaml
metadata:
  name: nginx-pod
  namespace: dev
```



```text
metadata
   |
   +-- name       → Pod's name
   |
   +-- namespace  → Which namespace the Pod belongs to
```

# 3. Pod

### What is Pod?

A **Pod is the smallest deployable unit in Kubernetes**.

Usually:

```text
Pod
 |
 +-- Container
      |
      +-- nginx
```

### Create Pod

```bash
kubectl run nginx --image=nginx
```

### Check Pod

```bash
kubectl get pods
```

### More information

```bash
kubectl get pods -o wide
```

This shows:

* Pod IP
* Node
* Status

### Describe Pod

```bash
kubectl describe pod nginx
```

This is extremely important for troubleshooting.

### See Pod logs

```bash
kubectl logs nginx
```

### Execute command inside Pod

```bash
kubectl exec -it nginx -- /bin/bash
```

For images without bash:

```bash
kubectl exec -it nginx -- /bin/sh
```

### Delete Pod

```bash
kubectl delete pod nginx
```

### Important demonstration

> "What happens if I delete a Pod created directly using `kubectl run`?"

Answer:

**The Pod disappears and Kubernetes does not recreate it**, because no controller owns it.

This leads naturally to **ReplicaSet**.

# 5. ReplicaSet

> "What if my application needs 3 Pods?"

This introduces ReplicaSet.

### What is ReplicaSet?

ReplicaSet maintains a desired number of Pod replicas.

```text
ReplicaSet
    |
    +---- Pod
    +---- Pod
    +---- Pod
```

### Create ReplicaSet using YAML

```yaml
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: nginx-rs
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
        - name: nginx
          image: nginx
          ports:
            - containerPort: 80
```

### Apply

```bash
kubectl apply -f replicaset.yaml
```

### Check

```bash
kubectl get replicaset
```

Short:

```bash
kubectl get rs
```

### Check Pods

```bash
kubectl get pods
```

You should see 3 Pods.

### Scale ReplicaSet

```bash
kubectl scale rs nginx-rs --replicas=5
```

### Verify

```bash
kubectl get pods
```

### Delete one Pod

```bash
kubectl delete pod <pod-name>
```

Then:

```bash
kubectl get pods
```

**Important demonstration:** Kubernetes automatically creates another Pod.

Explain:

> ReplicaSet continuously ensures that the desired number of Pods exists.

# 6. Deployment

> ReplicaSet maintains Pods, but how do we perform application updates and rollbacks?

Answer: **Deployment**.

### Relationship

```text
Deployment
     |
     ↓
ReplicaSet
     |
     +---- Pod
     +---- Pod
     +---- Pod
```

### Deployment YAML

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
        - name: nginx
          image: nginx:1.25
          ports:
            - containerPort: 80
```

### Apply

```bash
kubectl apply -f deployment.yaml
```

### Check Deployment

```bash
kubectl get deployments
```

Short:

```bash
kubectl get deploy
```

### Check ReplicaSet

```bash
kubectl get rs
```

### Check Pods

```bash
kubectl get pods
```

Show students:

```text
Deployment
     |
     ↓
ReplicaSet
     |
     ↓
Pods
```

# 8. Rolling Update

This is one of the most important DevOps concepts.

Current image:

```text
nginx:1.25
```

Change it to:

```text
nginx:1.27
```

Command:

```bash
kubectl set image deployment/nginx-deployment nginx=nginx:1.27
```

Check:

```bash
kubectl rollout status deployment/nginx-deployment
```

### Check rollout history

```bash
kubectl rollout history deployment/nginx-deployment
```

---

# 9. Rollback

If the new version has a problem:

```bash
kubectl rollout undo deployment/nginx-deployment
```

Check:

```bash
kubectl rollout status deployment/nginx-deployment
```

This is where you explain:

```text
Developer
   |
   ↓
New Version
   |
   ↓
Deployment
   |
   ↓
Rolling Update
   |
   ↓
Problem?
   |
   ↓
Rollback
```

# 10. Service

> Pod IPs can change.

So we need a **Service**.

### What is Service?

Service provides a stable network endpoint for Pods.

```text
              Service
                 |
       +---------+---------+
       |         |         |
      Pod       Pod       Pod
```

---

## Create Service

```yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx-service
spec:
  selector:
    app: nginx
  ports:
    - port: 80
      targetPort: 80
  type: ClusterIP
```

### Apply

```bash
kubectl apply -f service.yaml
```

### Check

```bash
kubectl get service
```

Short:

```bash
kubectl get svc
```

# 11. Service Port vs TargetPort


```text
Client
  |
  ↓
Service :80
  |
  ↓
targetPort :80
  |
  ↓
Pod :80
```

### `port`

Port exposed by the Service.

```yaml
port: 80
```

### `targetPort`

Port where the application is listening inside the Pod.

```yaml
targetPort: 80
```

They **do not have to be the same**.

Example:

```yaml
ports:
  - port: 8080
    targetPort: 80
```

Meaning:

```text
Client
  |
  ↓
Service :8080
  |
  ↓
Pod :80
```

---

# 12. Service Types


### ClusterIP

```yaml
type: ClusterIP
```

Internal communication.

```text
Pod → Service → Pod
```

---

### NodePort

```yaml
type: NodePort
```

Example:

```yaml
ports:
  - port: 80
    targetPort: 80
    nodePort: 30080
```

Traffic:

```text
Browser
   |
   ↓
NodeIP:30080
   |
   ↓
Service:80
   |
   ↓
Pod:80
```

Check:

```bash
kubectl get svc
```

---

### LoadBalancer

```yaml
type: LoadBalancer
```

Commonly used in cloud environments such as AWS.

```text
Internet
   |
   ↓
Cloud Load Balancer
   |
   ↓
Service
   |
   ↓
Pods
```

# 14. Labels and Selectors

This is a **very important Kubernetes concept**.

Pod:

```yaml
metadata:
  labels:
    app: nginx
```

Service:

```yaml
selector:
  app: nginx
```

Therefore:

```text
Service selector
      app=nginx
          |
          ↓
Find Pods with:
      app=nginx
```

Teach these commands:

```bash
kubectl get pods --show-labels
```

```bash
kubectl get pods -l app=nginx
```

Add label:

```bash
kubectl label pod nginx-pod environment=dev
```

# 16. Secret

For sensitive configuration.

Examples:

* Password
* Token
* API key

Create:

```bash
kubectl create secret generic db-secret \
  --from-literal=username=admin \
  --from-literal=password=admin123
```

Check:

```bash
kubectl get secrets
```

Describe:

```bash
kubectl describe secret db-secret
```

Explain:

> Kubernetes Secrets are intended for sensitive data, but students should not assume that simply putting a value in a Secret YAML makes it securely encrypted.

# 22. StatefulSet

Used for applications that require stable identity/storage.

Examples:

* MySQL
* PostgreSQL
* MongoDB
* Kafka
* Elasticsearch

Check:

```bash

```

Short:

```bash

```

Concept:

```text
StatefulSet
    |
    +-- mysql-0
    +-- mysql-1
    +-- mysql-2
```

Unlike normal Deployment Pods, StatefulSet Pods have stable identities.

# 28. Final Kubernetes Object Cheat Sheet

| Object          | Main Purpose                                    |
| --------------- | ----------------------------------------------- |
| **Cluster**     | Complete Kubernetes environment                 |
| **Node**        | Machine where workloads run                     |
| **Namespace**   | Logical resource isolation                      |
| **Pod**         | Smallest deployable unit                        |
| **ReplicaSet**  | Maintains desired number of Pods                |
| **Deployment**  | Manages ReplicaSets, updates and rollbacks      |
| **Service**     | Stable networking for Pods                      |
| **ConfigMap**   | Non-sensitive configuration                     |
| **Secret**      | Sensitive configuration                         |
| **PV**          | Persistent storage resource                     |
| **PVC**         | Request for persistent storage                  |
| **Ingress**     | HTTP/HTTPS routing                              |
| **DaemonSet**   | Pod on each eligible node                       |
| **StatefulSet** | Stateful workloads with stable identity/storage |
| **Job**         | Run task to completion                          |
| **CronJob**     | Schedule Jobs                                   |

ll give your fresher students a much stronger foundation than memorizing individual `kubectl` commands.
