# Day 3 — ReplicaSet & Deployment

## 🎯 Day 3 Objectives

By the end of Day 3, students should understand:

* Why standalone Pods are not enough
* What is a ReplicaSet?
* What is a Deployment?
* Desired state vs actual state
* Replicas
* Labels and selectors
* How Deployment creates ReplicaSets
* How ReplicaSet creates Pods
* Scaling
* Self-healing
* Rolling updates
* Rollback
* Important `kubectl` commands

---

# 1. Start With Yesterday's Problem

Ask students:

> Yesterday we created an Nginx Pod. What happens if the Pod crashes?

They should remember:

```text
Pod
 ↓
Container
```

If the Pod is deleted:

```text
nginx-pod ❌
```

It **does not automatically come back** because it was a standalone Pod.

Ask:

> "In production, do we want our application to disappear when one Pod fails?"

Obviously:

**No.**

We need Kubernetes to maintain the required number of Pods.

That's where **ReplicaSet** comes in.

---

# 2. What is a ReplicaSet?

Simple definition:

> **ReplicaSet ensures that the desired number of identical Pods are running.**

Suppose we want:

```text
replicas: 3
```

ReplicaSet maintains:

```text
Pod 1 ✅
Pod 2 ✅
Pod 3 ✅
```

If one Pod disappears:

```text
Pod 1 ✅
Pod 2 ❌
Pod 3 ✅
```

ReplicaSet notices:

```text
Desired = 3
Actual = 2
```

and creates another:

```text
Pod 1 ✅
Pod 2 ❌
Pod 3 ✅
Pod 4 ✅
```

Now:

```text
Actual = 3
```

---

# 3. Desired State vs Actual State

This is one of the most important Kubernetes concepts.

Suppose:

```text
Desired State = 3 Pods
```

Current situation:

```text
Actual State = 3 Pods
```

Everything is fine.

If one Pod crashes:

```text
Desired = 3
Actual  = 2
```

Kubernetes works to correct it:

```text
Actual 2
   ↓
ReplicaSet
   ↓
Create Pod
   ↓
Actual 3
```

This is the fundamental Kubernetes philosophy:

> **You tell Kubernetes what you want, and Kubernetes works to maintain that state.**

---

# 4. ReplicaSet Hands-On

Create:

```bash
vi replicaset.yaml
```

Use:

```yaml
apiVersion: apps/v1
kind: ReplicaSet

metadata:
  name: nginx-rs

spec:
  replicas: 3

  selector:
    matchLabels:
      app: nginx

  template:
    metadata:
      labels:
        app: nginx

    spec:
      containers:
        - name: nginx
          image: nginx:latest
          ports:
            - containerPort: 80
```

---

# 5. Explain the YAML

### `apiVersion`

```yaml
apiVersion: apps/v1
```

ReplicaSet belongs to the `apps` API group.

---

### `kind`

```yaml
kind: ReplicaSet
```

We're creating a ReplicaSet.

---

### `replicas`

```yaml
replicas: 3
```

We want:

```text
3 Pods
```

---

# 6. The Most Important Part — Selector

```yaml
selector:
  matchLabels:
    app: nginx
```

This tells the ReplicaSet:

> "Manage Pods having the label `app=nginx`."

---

# 7. Pod Template

```yaml
template:
  metadata:
    labels:
      app: nginx
```

This creates Pods with:

```text
app=nginx
```

Notice:

```text
Selector:

app: nginx

        ↓

Pod label:

app: nginx
```

They must match.

This is extremely important.

---

# 8. Create the ReplicaSet

```bash
kubectl apply -f replicaset.yaml
```

Expected:

```text
replicaset.apps/nginx-rs created
```

Check:

```bash
kubectl get rs
```

You should see:

```text
NAME       DESIRED   CURRENT   READY
nginx-rs   3         3         3
```

Now:

```bash
kubectl get pods
```

You'll see:

```text
nginx-rs-xxxxx   1/1   Running
nginx-rs-yyyyy   1/1   Running
nginx-rs-zzzzz   1/1   Running
```

Explain the Pod names.

They are generated by Kubernetes.

# 9. Test Self-Healing

This is the most important hands-on exercise.

First:

```bash
kubectl get pods
```

Pick one Pod.

For example:

```text
nginx-rs-abc123
```

Delete it:

```bash
kubectl delete pod nginx-rs-abc123
```

Immediately run:

```bash
kubectl get pods
```

You may see:

```text
nginx-rs-abc123   Terminating
nginx-rs-new456   ContainerCreating
nginx-rs-xyz789   Running
```

After a few seconds:

```bash
kubectl get pods
```

You'll have:

```text
3 Pods
```

### Ask students:

> "Who created the new Pod?"

Answer:

**ReplicaSet.**

This is the key lesson.

# 11. Now Introduce Deployment

Tell students:

> "ReplicaSet solves Pod availability, but we still need a better way to manage application releases and updates."

That's where **Deployment** comes in.

Simple definition:

> **A Deployment manages ReplicaSets and provides declarative application updates, scaling, rollout and rollback.**

The relationship is:

```text
Deployment
     |
     ↓
ReplicaSet
     |
     ↓
Pods
     |
     ↓
Containers
```

This diagram is extremely important.

---

# 12. Deployment Architecture

```text
             Deployment
                  |
                  ↓
             ReplicaSet
                  |
        +---------+---------+
        ↓         ↓         ↓
      Pod 1     Pod 2     Pod 3
        |         |         |
        ↓         ↓         ↓
    Container  Container  Container
```

In production, you'll normally create:

```text
Deployment
```

rather than manually creating ReplicaSets.

Kubernetes creates and manages the ReplicaSet for you.

---

# 13. Create Your First Deployment

First remove the ReplicaSet:

```bash
kubectl delete rs nginx-rs
```

Now create:

```bash
vi deployment.yaml
```

Use:

```yaml
apiVersion: apps/v1
kind: Deployment

metadata:
  name: nginx-deployment

spec:
  replicas: 3

  selector:
    matchLabels:
      app: nginx

  template:
    metadata:
      labels:
        app: nginx

    spec:
      containers:
        - name: nginx
          image: nginx:1.27
          ports:
            - containerPort: 80
```

# 17. Rolling Update

This is where Deployment becomes much more powerful.

Current image:

```yaml
image: nginx:1.27
```

Change it to:

```yaml
image: nginx:1.28
```

Then:

```bash
kubectl apply -f deployment.yaml
```

Watch the rollout:

```bash
kubectl rollout status deployment nginx-deployment
```

You can also watch Pods:

```bash
kubectl get pods -w
```

Kubernetes gradually replaces the old Pods with new Pods.

Conceptually:

```text
Old Version
   |
   +--- Pod v1
   +--- Pod v1
   +--- Pod v1
```

During rollout:

```text
Pod v1
Pod v1
Pod v2
```

Eventually:

```text
Pod v2
Pod v2
Pod v2
```

This is a **rolling update**.

---

# 18. Check Deployment History

Run:

```bash
kubectl rollout history deployment nginx-deployment
```

This shows rollout revisions.

---

# 19. Rollback

Suppose version 2 has a problem.

You can rollback:

```bash
kubectl rollout undo deployment nginx-deployment
```

Check:

```bash
kubectl rollout status deployment nginx-deployment
```

This is an extremely important DevOps concept:

```text
Version 1
   ↓
Version 2
   ↓
Problem ❌
   ↓
Rollback
   ↓
Version 1 ✅
```

```text

   ↓
Gradually replaced
   ↓

```

# 21. Deployment vs ReplicaSet vs Pod

This is the most important comparison of Day 3.

| Object         | Main responsibility                          |
| -------------- | -------------------------------------------- |
| **Pod**        | Runs container(s)                            |
| **ReplicaSet** | Maintains desired number of Pods             |
| **Deployment** | Manages ReplicaSets and application releases |

Remember:

```text
Deployment
     ↓
ReplicaSet
     ↓
Pod
     ↓
Container
```

---

# 22. Very Important — Don't Say Deployment "Runs Containers"

Students often say:

> "Deployment runs containers."

Correct them.

More accurately:

```text
Deployment
    ↓
ReplicaSet
    ↓
Pod
    ↓
Container
```

Deployment manages the application workload through ReplicaSets and Pods.

# 23. Labels and Selectors

Spend some time on this because students will repeatedly encounter it.

Pod:

```yaml
labels:
  app: nginx
```

Deployment selector:

```yaml
selector:
  matchLabels:
    app: nginx
```

Think:

```text
Label
  ↓
Identifies Pod

Selector
  ↓
Finds matching Pods
```

This becomes **very important on Day 4 when you teach Services**.

# 24. Day 3 Troubleshooting Exercise

Give students a broken Deployment:

```yaml
apiVersion: apps/v1
kind: Deployment

metadata:
  name: nginx-test

spec:
  replicas: 3

  selector:
    matchLabels:
      app: nginx

  template:
    metadata:
      labels:
        app: web

    spec:
      containers:
        - name: nginx
          image: nginx:latest
```

Ask:

> "What is wrong?"

The selector says:

```text
app: nginx
```

But the Pod template says:

```text
app: web
```

They don't match.

This teaches students why **labels and selectors are critical**.

# 🎯 Day 3 Interview Questions

Students should be able to answer these:

### 1. Why do we need ReplicaSet?

To maintain the desired number of Pods.

### 2. What happens if a Pod managed by ReplicaSet is deleted?

ReplicaSet creates a replacement Pod.

### 3. What is a Deployment?

A Kubernetes object used to manage application deployments, ReplicaSets, scaling, rolling updates and rollbacks.

### 4. What is the relationship between Deployment, ReplicaSet and Pod?

```text
Deployment
    ↓
ReplicaSet
    ↓
Pod
```

### 5. What is a replica?

A copy/instance of an application Pod.

### 6. What is a rolling update?

Gradually replacing old application Pods with new-version Pods.

### 7. How do you rollback a Deployment?

```bash
kubectl rollout undo deployment <deployment-name>
```

### 8. How do you scale a Deployment?

```bash
kubectl scale deployment <name> --replicas=5
```

### 9. Why are labels important?

They identify resources and allow selectors to find matching resources.
