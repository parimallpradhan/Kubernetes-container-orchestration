# Kubernetes YAML Files 

> **"How do we tell Kubernetes what we want to create?"**

Answer:

> **Using Kubernetes resource manifests, commonly written in YAML.**

The key concept is:

```text
YAML File
   ↓
kubectl
   ↓
Kubernetes API Server
   ↓
Kubernetes Object
```

---

## 1. What is YAML?

YAML stands for:

> **YAML Ain't Markup Language**

It is a human-readable data serialization format.

Simple example:

```yaml
name: nginx
version: "1.0"
environment: production
```

Explain that YAML mainly represents **data and configuration**, not programming logic.

---

# 2. Why Kubernetes uses YAML

Without YAML, you could create resources using imperative commands:

```bash
kubectl create deployment nginx --image=nginx
```

But in real projects, we often want the configuration stored as code:

```text
nginx-deployment.yaml
```

Then:

```bash
kubectl apply -f nginx-deployment.yaml
```

Architecture:

```text
Developer
   |
   v
YAML Manifest
   |
   v
kubectl apply
   |
   v
API Server
   |
   v
Kubernetes
   |
   v
Resource
```

This introduces students to **Infrastructure/Configuration as Code** concepts.

---

# 3. YAML basic syntax

Teach these rules carefully.

### Key-value

```yaml
name: nginx
image: nginx
port: 80
```

### Nested data

Indentation is extremely important.

```yaml
app:
  name: nginx
  version: "1.0"
```

The spaces represent hierarchy.

# 4. Lists

Example:

```yaml
fruits:
  - apple
  - banana
  - mango
```

Another example:

```yaml
ports:
  - 80
  - 443
```

Explain:

```text
-
```

represents an item in a YAML list.

---

# 5. YAML indentation

This is one of the most important beginner concepts.

Correct:

```yaml
app:
  name: nginx
  version: "1.0"
```

Incorrect:

```yaml
app:
 name: nginx
    version: "1.0"
```

Tell students:

> **YAML is indentation-sensitive.**

Use spaces, not tabs.

---

# 6. Comments

```yaml
# This is a comment
name: nginx
```

Comments are ignored.

This is useful for documenting Kubernetes manifests.

---

# 7. Strings, numbers and booleans

Examples:

```yaml
name: nginx
replicas: 3
enabled: true
environment: production
```

Teach students to be careful with values that YAML may interpret as numbers, booleans, dates, etc.

For values intended explicitly as strings, quotes can help:

```yaml
version: "1.0"
port: "8080"
```

---

# 8. Kubernetes YAML structure

Now introduce the **most important Kubernetes concept**.

Most Kubernetes manifests commonly contain:

```yaml
apiVersion:
kind:
metadata:
spec:
```

For example:

```yaml
apiVersion: apps/v1
kind: Deployment

metadata:
  name: nginx-deployment

spec:
  replicas: 3
```

Explain each one.

---

# 9. `apiVersion`

Example:

```yaml
apiVersion: apps/v1
```

It tells Kubernetes which API version is used for the resource definition.

Examples:

```yaml
apiVersion: v1
```

```yaml
apiVersion: apps/v1
```

```yaml
apiVersion: batch/v1
```

Don't ask students to memorize every API version. Teach them to look at the documentation for the resource they are creating.

---

# 10. `kind`

This tells Kubernetes:

> **What type of object are we creating?**

Examples:

```yaml
kind: Pod
```

```yaml
kind: Deployment
```

```yaml
kind: Service
```

```yaml
kind: ConfigMap
```

```yaml
kind: Secret
```

---

# 11. `metadata`

Metadata identifies and describes the object.

Example:

```yaml
metadata:
  name: nginx
```

You will commonly see:

```yaml
metadata:
  name: nginx
  labels:
    app: nginx
```

Explain:

```text
metadata
   |
   +-- name
   |
   +-- labels
   |
   +-- annotations
```

---

# 12. `spec`

This is extremely important.

Tell students:

> **`spec` describes the desired configuration of the Kubernetes object.**

For example:

```yaml
spec:
  replicas: 3
```

means:

> "I want 3 replicas."

This connects directly to the concept you taught earlier:

```text
Desired State
     ↓
spec
```

---

# 13. First Kubernetes YAML — Pod

Now create their first manifest.

```yaml
apiVersion: v1
kind: Pod

metadata:
  name: nginx-pod

spec:
  containers:
    - name: nginx
      image: nginx
      ports:
        - containerPort: 80
```

Explain it line by line.

```text
apiVersion
    ↓
Which API?

kind
    ↓
What object?

metadata
    ↓
Object identity

spec
    ↓
What do we want?

containers
    ↓
What container should run?
```

pod.yaml

```bash

```

```bash

```

# 15. Imperative vs Declarative

This is **very important for DevOps students**.

### Imperative

You tell Kubernetes **what command to execute**.

```bash
kubectl create deployment nginx --image=nginx
```

### Declarative

You describe **the desired state**.

```yaml
spec:
  replicas: 3
```

Then:

```bash
kubectl apply -f deployment.yaml
```

Kubernetes determines what actions are needed to reach that desired state.

Show:

```text
Imperative

You
 |
 | "Create this"
 v
Kubernetes
```

Versus:

```text
Declarative

You
 |
 | "This is what I want"
 v
YAML
 |
 v
Kubernetes
 |
 v
Desired State
```

This is a foundational Kubernetes concept.

# 16. Deployment YAML

After Pod YAML, introduce Deployment.

```yaml
apiVersion: apps/v1
kind: Deployment

metadata:
  name: nginx-deployment

spec:
  replicas: 3

  selector:
    matchLabels:
      app: nginx

  template:
    metadata:
      labels:
        app: nginx

    spec:
      containers:
        - name: nginx
          image: nginx
          ports:
            - containerPort: 80
```

Don't rush this.

Explain the hierarchy:

```text
Deployment
    |
    v
ReplicaSet
    |
    v
Pods
    |
    v
Containers
```

And:

```text
Deployment YAML
      |
      v
Desired replicas = 3
      |
      v
Kubernetes
      |
 +----+----+----+
 |    |    |    |
Pod  Pod  Pod
```

---

# 17. Labels and Selectors

This deserves special attention.

Example:

```yaml
labels:
  app: nginx
```

and:

```yaml
selector:
  matchLabels:
    app: nginx
```

Explain:

> **Labels identify/group resources, and selectors are used to select resources matching those labels.**

Think:

```text
Pod 1 → app=nginx
Pod 2 → app=nginx
Pod 3 → app=nginx

Selector:
app=nginx

        ↓

Matches all 3 Pods
```

This becomes extremely important when you teach Services.

---

# 18. Service YAML

Then show:

```yaml
apiVersion: v1
kind: Service

metadata:
  name: nginx-service

spec:
  selector:
    app: nginx

  ports:
    - port: 80
      targetPort: 80

  type: ClusterIP
```

Now students can understand:

```text
Service
   |
selector: app=nginx
   |
+--+--+--+
|  |  |  |
Pod Pod Pod
```

---

# 19. Multiple YAML objects in one file

This is useful to teach.

You can have:

```yaml
apiVersion: apps/v1
kind: Deployment
...
---
apiVersion: v1
kind: Service
...
```

The separator:

```yaml
---
```

means another YAML document follows.

Then:

```bash
kubectl apply -f app.yaml
```

can create both resources.

# 21. YAML mistakes students will commonly make

Show them these early.

### Wrong indentation

```yaml
metadata:
name: nginx
```

Correct:

```yaml
metadata:
  name: nginx
```

### Wrong API version

```yaml
apiVersion: apps/v1
kind: Pod
```

The API version must match the resource's API.

### Wrong selector

```yaml
selector:
  matchLabels:
    app: nginx
```

but Pod template has:

```yaml
labels:
  app: web
```

The Deployment selector and Pod template labels must be compatible.

### Typo

```yaml
replicass: 3
```

instead of:

```yaml
replicas: 3
```

# 22. Teach validation before applying

This is a very useful DevOps habit.

Students can use:

```bash
kubectl apply --dry-run=client -f deployment.yaml
```

They can also inspect the API schema:

```bash
kubectl explain deployment
```

And:

```bash
kubectl explain deployment.spec
```

Then:

```bash
kubectl explain deployment.spec.template
```

This teaches students that Kubernetes itself can help them understand resource fields.

# 24. What students should remember

Give them this mental model:

```text
                 Kubernetes YAML

                apiVersion
                     |
                   kind
                     |
                  metadata
                     |
                   spec
                     |
             Desired State
                     |
                     v
              kubectl apply
                     |
                     v
                API Server
                     |
                     v
                 Kubernetes
                     |
                     v
             Actual Resources
```

### Golden rule

> **`apiVersion` + `kind` + `metadata` + `spec` = the basic mental model for Kubernetes manifests.**

And don't teach YAML as merely "syntax."

Teach it as:

> **YAML is how we declaratively describe the desired state of Kubernetes resources.**

That prepares students perfectly for your next sequence:

**Pod YAML → Deployment YAML → ReplicaSet → Service YAML → Namespace → ConfigMap → Secret → Volume → Ingress.**
