# What is a Service in Kubernetes?

A **Kubernetes Service** provides a **stable network address** to access Pods and distributes traffic between them.

### Example

Pods can be created and deleted, so their **IP addresses can change**.

Instead of connecting directly to Pods:

```text
❌ Frontend → Pod IP
             10.0.1.10
```

we use a Service:

```text
                 Frontend
                    │
                    ▼
              ┌───────────┐
              │  Service  │
              │ backend   │
              └─────┬─────┘
                    │
             ┌──────┼──────┐
             ▼      ▼      ▼
           Pod 1  Pod 2  Pod 3
```

### One-line explanation

> **Service = A stable network endpoint that allows applications to communicate with Pods.**

### Why do we need Services?

```text
Pod
 │
 ├── IP can change
 ├── Pod can be deleted
 └── New Pod can be created
```

The Service remains stable:

```text
Frontend
   │
   ▼
backend-service
   │
   ├── Pod 1
   ├── Pod 2
   └── Pod 3
```

So the frontend doesn't need to know the individual Pod IP addresses.

### Types of Kubernetes Services

For students, teach them in this order:

```text
Kubernetes Services
       │
       ├── ClusterIP
       │
       ├── NodePort
       │
       ├── LoadBalancer
       │
       └── ExternalName
```

**Easy way to remember:**

* **ClusterIP** → Internal access
* **NodePort** → Access from outside using Node IP + Port
* **LoadBalancer** → External access through a cloud Load Balancer
* **ExternalName** → Maps a Service to an external DNS name

# Types of Kubernetes Services

A **Kubernetes Service** provides a stable way to access a group of Pods.

There are **4 main Service types**:

```text
                Kubernetes Services
                       │
        ┌──────────────┼──────────────┐
        │              │              │
        ▼              ▼              ▼
    ClusterIP       NodePort      LoadBalancer
        │              │              │
    Internal       External        External
     access         access          access

                       +
                       │
                       ▼
                  ExternalName
```

## 1. ClusterIP

**ClusterIP is used for communication inside the Kubernetes cluster.**

```text
Frontend Pod
     │
     ▼
ClusterIP Service
     │
 ┌───┼───┐
 ▼   ▼   ▼
Pod Pod Pod
```

Example:

```bash
kubectl expose deployment nginx --type=ClusterIP --port=80
```

**Use case:** Backend service communicating with database or frontend.

> **ClusterIP → Internal access**

---

## 2. NodePort

**NodePort exposes the Service outside the cluster using the Worker Node's IP and a port.**

```text
Browser
   │
   ▼
Node IP:30080
   │
   ▼
NodePort Service
   │
 ┌─┼─┐
 ▼ ▼ ▼
Pod Pod Pod
```

Example:

```bash
kubectl expose deployment nginx \
  --type=NodePort \
  --port=80
```

Kubernetes typically assigns a port from:

```text
30000 - 32767
```

Example:

```text
http://<Node-IP>:30080
```

> **NodePort → External access using Node IP + Port**

---

## 3. LoadBalancer

**LoadBalancer creates/provides an external Load Balancer to expose the application to the internet, commonly in cloud environments.**

```text
                Internet
                    │
                    ▼
             Cloud Load Balancer
                    │
                    ▼
            LoadBalancer Service
                    │
             ┌──────┼──────┐
             ▼      ▼      ▼
            Pod    Pod    Pod
```

Example:

```bash
kubectl expose deployment nginx \
  --type=LoadBalancer \
  --port=80
```

In AWS EKS, this can provision an AWS load-balancing resource depending on the cluster configuration and controller in use.

> **LoadBalancer → Internet-facing access**

---

## 4. ExternalName

**ExternalName maps a Kubernetes Service to an external DNS name instead of routing traffic to Pods.**

```text
Application
     │
     ▼
ExternalName Service
     │
     ▼
External System
example.com
```

Example:

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  type: ExternalName
  externalName: example.com
```

> **ExternalName → Access an external service by a Kubernetes Service name**

---

# Easy Way to Remember

| Type             | Access               | Simple Example         |
| ---------------- | -------------------- | ---------------------- |
| **ClusterIP**    | Inside cluster       | Backend → Database     |
| **NodePort**     | Outside via Node IP  | Browser → Node         |
| **LoadBalancer** | Outside via Cloud LB | Internet → Application |
| **ExternalName** | External DNS         | App → External service |

### Student-friendly analogy

```text
ClusterIP
   ↓
"Only people inside the building"

NodePort
   ↓
"Enter through a specific building door"

LoadBalancer
   ↓
"Receptionist distributes visitors to available rooms"

ExternalName
   ↓
"Redirect to another building"
```

**Recommended teaching order:**
**ClusterIP → NodePort → LoadBalancer → ExternalName**, with a hands-on example for the first three.
