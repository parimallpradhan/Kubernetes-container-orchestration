# What is a Service in Kubernetes?

A **Kubernetes Service** provides a **stable network address** to access Pods and distributes traffic between them.

### Example

Pods can be created and deleted, so their **IP addresses can change**.

Instead of connecting directly to Pods:

```text
❌ Frontend → Pod IP
             10.0.1.10
```

we use a Service:

```text
                 Frontend
                    │
                    ▼
              ┌───────────┐
              │  Service  │
              │ backend   │
              └─────┬─────┘
                    │
             ┌──────┼──────┐
             ▼      ▼      ▼
           Pod 1  Pod 2  Pod 3
```

### One-line explanation

> **Service = A stable network endpoint that allows applications to communicate with Pods.**

### Why do we need Services?

```text
Pod
 │
 ├── IP can change
 ├── Pod can be deleted
 └── New Pod can be created
```

The Service remains stable:

```text
Frontend
   │
   ▼
backend-service
   │
   ├── Pod 1
   ├── Pod 2
   └── Pod 3
```

So the frontend doesn't need to know the individual Pod IP addresses.

### Types of Kubernetes Services

For students, teach them in this order:

```text
Kubernetes Services
       │
       ├── ClusterIP
       │
       ├── NodePort
       │
       ├── LoadBalancer
       │
       └── ExternalName
```

**Easy way to remember:**

* **ClusterIP** → Internal access
* **NodePort** → Access from outside using Node IP + Port
* **LoadBalancer** → External access through a cloud Load Balancer
* **ExternalName** → Maps a Service to an external DNS name
