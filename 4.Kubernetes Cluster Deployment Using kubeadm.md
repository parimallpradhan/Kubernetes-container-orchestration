# 2. what kubeadm is?


> **kubeadm is a Kubernetes tool used to bootstrap a Kubernetes cluster.**

### kubeadm is NOT Kubernetes itself.

Think:

```text
Kubernetes
    |
    +--- kubeadm → creates/bootstrap cluster
    |
    +--- kubectl → communicates with cluster
    |
    +--- kubelet → runs on nodes
```
Three tools:

| Tool      | Purpose                      |
| --------- | ---------------------------- |
| `kubeadm` | Create/bootstrap the cluster |
| `kubectl` | Manage the cluster           |
| `kubelet` | Agent running on each node   |

# 6. Disable Swap

This is an important kubeadm prerequisite.

Check:

```bash
free -h
```

Check swap:

```bash
swapon --show
```

Disable:

```bash
sudo swapoff -a
```

To disable it across reboots, remove/comment the swap entry in `/etc/fstab` appropriately.

Then verify:

```bash
free -h
```

Explain why:

> kubelet expects swap to be disabled by default for a standard kubeadm cluster setup.

# 8. Install containerd

On Ubuntu, install:

```bash
sudo apt update
sudo apt install -y containerd
```

Check:

```bash
containerd --version
```

Enable it:

```bash
sudo systemctl enable --now containerd
```

Check:

```bash
sudo systemctl status containerd
```

---

# 9. Configure containerd

This is an important practical step.

Create the configuration directory if needed:

```bash
sudo mkdir -p /etc/containerd
```

Generate the default configuration:

```bash
containerd config default | sudo tee /etc/containerd/config.toml
```

For Kubernetes, configure the runtime to use the **systemd cgroup driver**.

The relevant configuration is under the `runc` options in:

```text
/etc/containerd/config.toml
```

Set:

```text
SystemdCgroup = true
```

Then restart:

```bash
sudo systemctl restart containerd
```

Verify:

```bash
sudo systemctl status containerd
```

### Teaching point

Explain:

> **kubelet and the container runtime should use compatible cgroup configuration.**

# 11. Initialize the Control Plane

This is the most exciting part for students.

On the **Control Plane**:

```bash
sudo kubeadm init --pod-network-cidr=<CNI-POD-CIDR>
```

The exact Pod CIDR should match the CNI plugin you plan to install.

For example, if your chosen CNI documentation specifies `10.244.0.0/16`, use that value.

Explain:

> `kubeadm init` initializes the Kubernetes Control Plane.

Conceptually:

```text
kubeadm init
     |
     +---- API Server
     +---- Scheduler
     +---- Controller Manager
     +---- etcd
     +---- Certificates
     +---- kubeconfig
```

---

# 12. Very Important: Save the kubeadm join command

At the end, kubeadm will display a command similar to:

```bash
kubeadm join <CONTROL-PLANE-IP>:6443 \
  --token <TOKEN> \
  --discovery-token-ca-cert-hash sha256:<HASH>
```

Tell students:

> **Do not lose this command. Worker nodes use it to join the cluster.**

Don't have students copy a command from the internet. They must use the **join command generated by their own control plane**.

---

# 13. Configure kubectl

After initializing the control plane, configure the current user to use the cluster.

For example:

```bash
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown "$(id -u)":"$(id -g)" $HOME/.kube/config
```

Then:

```bash
kubectl get nodes
```

Initially they may see:

```text
NAME       STATUS     ROLES           AGE
master     NotReady   control-plane   1m
```

This is a **great teaching moment**.

Ask:

> "Why is my Control Plane NotReady?"

Because you haven't installed a **Pod network/CNI** yet.

---

# 14. Explain CNI

Tell students:

> **CNI provides networking for Kubernetes Pods.**

Architecture:

```text
Kubernetes
     |
    CNI
     |
+----+----+----+
|    |    |    |
Pod  Pod  Pod  Pod
```

Examples of CNI plugins include:

* Calico
* Cilium
* Flannel

For a classroom kubeadm lab, choose **one** and use its current official installation instructions.

Don't mix different CNI instructions.

# 15. Install the Pod Network

After installing your selected CNI, check:

```bash
kubectl get pods -A
```

Then:

```bash
kubectl get nodes
```

Eventually:

```text
NAME       STATUS   ROLES           AGE
master     Ready    control-plane   10m
```

Explain:

> **Ready means the node is healthy and able to participate in running Kubernetes workloads.**

---

# 16. Join Worker Node

Now move to the Worker.

Run the `kubeadm join` command generated earlier:

```bash
sudo kubeadm join <CONTROL-PLANE-IP>:6443 \
  --token <TOKEN> \
  --discovery-token-ca-cert-hash sha256:<HASH>
```

Then go back to the Control Plane:

```bash
kubectl get nodes
```

You should eventually see:

```text
NAME       STATUS   ROLES           AGE
master     Ready    control-plane   20m
worker1    Ready    <none>          5m
```

🎉

Tell students:

> **"Congratulations. We have created a Kubernetes cluster."**

# 17. What happened internally?

This is very important.

```text

      |

      +---- etcd
      +---- Scheduler

      |

      |
```

# 23. Important classroom warning

Don't teach students to blindly run random commands from blogs.

For Kubernetes installation, versions and repository instructions change.

Your teaching pattern should be:

```text
Official Kubernetes documentation
          ↓
Choose Kubernetes version
          ↓
Install kubeadm/kubelet/kubectl
          ↓
Configure containerd
          ↓
kubeadm init
          ↓
CNI
          ↓
kubeadm join
```

Also, **don't use old Docker-centric kubeadm tutorials without checking them**. Modern Kubernetes uses CRI-compatible runtimes, and `dockershim` was removed from Kubernetes years ago.
